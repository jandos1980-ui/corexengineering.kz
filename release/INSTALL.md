# Установка CoreX Engineering

Архив предназначен для https://corexengineering.kz/ в корне домена. Это готовый статический сайт RU/KK/EN. Для прямой отправки заявок необходимы PHP 8.1+ и настроенный почтовый транспорт сервера. Node.js, npm, Python и база данных в работе сайта не используются.

## Состав

- `site/` — готовые файлы сайта. Только содержимое этой папки размещается в web root.
- `VERSION.txt` — исходный коммит и домен.
- `SHA256SUMS.txt` — контрольные суммы файлов.
- `INSTALL.md` — эта инструкция; держите её вне публичной папки.

Редактор типографики, тесты, отчёты, Git-история, исходные TTF, лишние PNG и неиспользуемые видео в комплект не входят. Лицензии используемых шрифтов сохранены в assets.

## Предварительная проверка и перенос

1. Распакуйте архив. Сохраните вложенность `assets`, `components`, `documents`, `solutions`, `kk`.
2. Разместите содержимое `site/` в корне виртуального хоста. `index.html` должен лежать непосредственно в web root, без дополнительной папки `site` в URL.
3. Настройте домен `corexengineering.kz`, сертификат HTTPS, перенаправление HTTP → HTTPS и `www` → адрес без `www`. Примеры ниже — фрагменты для существующей конфигурации хостинга, не готовая настройка TLS.
4. До переключения DNS проверьте новый сервер через локальную запись hosts или закрытый тестовый хост. Производственный архив разрешает индексацию: тестовый хост должен быть защищён авторизацией или HTTP-заголовком `X-Robots-Tag: noindex`. На основном домене этот заголовок необходимо убрать.
5. Перед заменой Tilda сохраните её настройки и возможность возврата. Меняйте только DNS-записи веб-сайта, сохраняя почтовые MX/TXT. Сам архив не меняет DNS и не отключает Tilda. Переключение выполняет администратор клиента после проверки.

## Nginx

В HTTPS server-блоке для основного домена укажите свой путь:

```nginx
root /var/www/corexengineering;
index index.html;
location / {
    try_files $uri $uri/ =404;
}
error_page 404 /404.html;
```

Проверьте конфигурацию `nginx -t` перед перезагрузкой. Подключите стандартный `mime.types` Nginx; сервер должен корректно отдавать CSS, JS, WebP, WOFF2 и PDF. Не направляйте неизвестные пути на главную со статусом 200.

## Apache

В конфигурации сайта или `.htaccess` (если разрешены соответствующие директивы):

```apache
DirectoryIndex index.html
ErrorDocument 404 /404.html
```

Настройте HTTPS и перенаправления средствами хостинга. Страница ошибки должна сохранять HTTP 404. Серверные конфигурации и сертификаты в ZIP не включены: они зависят от окружения клиента.

## Индексация

Все 24 страницы разрешены к индексации. Canonical, hreflang, og:url и sitemap используют https://corexengineering.kz/. `404.html` имеет noindex. robots.txt и sitemap.xml должны открываться в корне домена. На другом домене или в подпапке эту сборку без обновления адресов не публикуйте.

После запуска добавьте `https://corexengineering.kz/sitemap.xml` в подтверждённые Google Search Console и Яндекс Вебмастер, запросите проверку главной RU/KK/EN. Публикация и sitemap не гарантируют сроки индексации. Демоверсия GitHub Pages намеренно остаётся с noindex; скачивайте именно `corex-site.zip` из Assets релиза, а не автоматический Source code ZIP.

## Заявки и редактирование

Форма отправляет JSON POST на `api/contact.php` на том же домене. Получатель фиксирован: `info@corexengineering.kz`. Обязательны имя, компания, email и задача. Поля из одних пробелов не принимаются. Email: один адрес, без внутренних пробелов, локальная часть до 64 символов, весь адрес до 254, домен с точкой и корректными метками до 63 символов; точки подряд и по краям локальной части запрещены. Допускаются адреса с плюсом и поддоменами. Проверка формата не подтверждает существование ящика. RU/EN/KK используют единый обработчик и переведённые сообщения. Почтовая программа посетителя не нужна. GitHub Pages и обычный статический сервер PHP не исполняют: на них отправка не работает.

### Настройка программистом

1. Подключите PHP 8.1+ к `/api/contact.php` средствами хостинга (Apache handler или Nginx PHP-FPM). Не допускайте выдачу PHP как исходного текста. Пример Nginx выше обслуживает только статические файлы и требует дополнения PHP location по инструкции хостинга.
2. Настройте `mail()` через почтовый транспорт хостинга, авторизованный для отправителя `website@corexengineering.kz`. Настройте SPF/DKIM и проверьте DMARC. Если хостинг требует SMTP-библиотеку, замените вызов `mail()` на его SMTP-транспорт на сервере; секреты храните вне web root и Git. `Reply-To` уже содержит проверенный email посетителя.
3. Создайте закрытый каталог вне web root, доступный на запись только PHP-пользователю (например `/var/lib/corex-contact`, права 0700). Задайте серверные переменные окружения: `COREX_CONTACT_RATE_DIR` — абсолютный путь к нему; `COREX_CONTACT_RATE_SALT` — случайная строка не короче 32 символов (можно сгенерировать `openssl rand -hex 32`). Переменные должны быть доступны PHP-FPM, а не только интерактивной оболочке.
4. Только после настройки почты задайте `COREX_CONTACT_ENABLED=1`. По умолчанию обработчик возвращает 503. Разрешённые Origin — `https://corexengineering.kz` и `https://www.corexengineering.kz`; для закрытого тестового домена временно добавьте точный Origin в обработчик и удалите его после проверки.
5. Ограничьте размер тела POST на сервере до 16 КБ. Включите `display_errors=Off`, серверное логирование ошибок без тела заявок. Обработчик возвращает только JSON. Не перенаправляйте API на главную сайта.
6. Проверяйте `REMOTE_ADDR` за прокси: доверенные прокси настраиваются на сервере. Не подставляйте произвольный клиентский X-Forwarded-For. Лимит — 5 попыток в час на IP, не чаще раза в минуту; общая сеть посетителей делит лимит. Honeypot и Origin — базовые меры, не полноценная защита от ботов; при атаке подключите ограничения хостинга/WAF.

Содержимое заявки обработчик не записывает на диск; email поступает в почтовую систему. Закрытый файл лимитов содержит хеши IP и время, устаревшие записи удаляются при следующих запросах. Успешный ответ означает принятие письма почтовым транспортом, не гарантирует доставку в ящик. Проверьте реальные входящие и спам перед запуском.

### Обязательная проверка на хостинге

- `php -l api/contact.php` — проверка PHP.
- Тестовая заявка с главной и внутренней страницы каждого языка: правильный получатель, все поля, кириллица/казахские символы и рабочий Reply-To.
- Неверный email/пустая задача → 422, GET → 405, чужой Origin → 403, частые запросы → 429; при выключенном обработчике → 503.
- При ошибке сервера или сети текст остаётся в форме; подтверждение успеха не показывается. Во время запроса повторное нажатие заблокировано. После тайм-аута письмо могло уже уйти: проверьте ящик перед повторной отправкой.
- Без JavaScript остаётся ссылка на email. Убедитесь, что письма реально приходят на `info@corexengineering.kz`, затем проверьте ответ посетителю.

До успешной загрузки обработчика форма скрыта, её поля отключены. Без JavaScript или при ошибке загрузки app.js посетителю доступна прямая ссылка на почту; введённые данные не отправляются через GET. Не удаляйте атрибуты hidden/disabled из исходного HTML без замены этого механизма.

Тексты редактируются в HTML; главная RU — index.html, KK — kk/index.html. Страницы направлений находятся в solutions и kk/solutions. Изображения и шрифты локальные. После изменения CSS/JS обновляйте параметры версий в HTML или сбрасывайте кэш на сервере.

Редактор типографики доступен отдельно: https://github.com/jandos1980-ui/corex-typography-editor.

## Приёмка на сервере клиента

- Главная `/`, `/kk/`, `/en/` и все 21 страницы направлений открываются со статусом 200.
- Переключатель языка, меню, карточки оборудования, FAQ и PDF работают.
- Проверьте экран 320–390 px и desktop, загрузку изображений и шрифтов.
- Проверьте прямую отправку формой и реальное получение заявки на info@corexengineering.kz.
- `/несуществующая-страница/` возвращает 404 с оформленной страницей, `/robots.txt` и `/sitemap.xml` — 200.
- Проверьте также вложенный ошибочный адрес `/kk/несуществующая/страница/`: оформление 404 сохраняется, кнопка возвращает на `/`. Стили 404 встроены в HTML, JavaScript для неё не нужен.
- В HTML основных страниц нет noindex; в HTTP-ответах нет X-Robots-Tag: noindex. Canonical указывает на текущую страницу HTTPS.
- HTTP и www перенаправляются на HTTPS без www, без циклов; почта домена продолжает работать.

Архив проверен на локальном сервере после распаковки. Настройки DNS, TLS, почты, серверные заголовки и индексацию нужно проверить после установки в окружении клиента.
